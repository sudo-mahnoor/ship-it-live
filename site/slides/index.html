The words

CI, CD and CD

Continuous Integration

Push small changes often. Every push is built and tested automatically, so problems show up in minutes, not weeks.

Continuous Delivery

Every change that passes is ready to release. A person still presses the final "deploy" button.

Continuous Deployment

Every change that passes goes live automatically. No button, no waiting.

The golden rule

If any step fails, nothing ships. The last good version stays live.

In today's demo

We use Continuous Deployment: one git push, and your phones update.

Under the hood

Inside a pipeline

Trigger

What starts it: a push, a pull request or a schedule.

Job and steps

A job is a list of steps. Each step is one command, like "run the tests".

Runner

A fresh cloud machine that runs the job, then disappears.

# .github/workflows/pipeline.yml on: push: branches: [main] # trigger jobs: test: runs-on: ubuntu-latest # runner steps: - uses: actions/checkout@v4 - run: python tests/check_site.py deploy: needs: test # only if tests pass runs-on: ubuntu-latest steps: - uses: actions/deploy-pages@v4

Branch protection rules

  • No direct pushes to main
  • CI checks must pass before merge
  • At least one approval from a teammate

Why teams do this

  • Main is always working and deployable
  • Two pairs of eyes catch more bugs
  • Every change has a story you can read later

Security

Keep secrets out of code

Never

  • Hardcode API keys or passwords in code
  • Commit your .env file
  • Paste keys in chats or screenshots

Instead

  • Environment variables
  • GitHub Secrets or a cloud secret manager
  • Different keys for dev, staging and production

If a key leaks

  • Revoke and replace it right away
  • Deleting the commit is not enough. Git history keeps it
  • Check the usage and the bill
# in the workflow file env: API_KEY: ${{ secrets.API_KEY }}

Bots scan public GitHub repos for keys all day. A leaked cloud key can be abused within minutes.

The cloud

Where can you deploy?

Static sites and frontends

GitHub Pages, Vercel, Netlify

Portfolios, landing pages, React and Next.js apps. Free tiers to start.

Full-stack apps and APIs

Render, Railway, Fly.io

Backends, databases, bots. Push code and the platform runs it.

Full control at scale

AWS, Azure, Google Cloud

Servers, networks, Kubernetes. What most companies run on.

Docker

Package your app with everything it needs. It runs the same on your laptop, in CI and in the cloud.

Infrastructure as Code

Tools like Terraform describe servers in code. No more clicking around a console and forgetting what you did.
